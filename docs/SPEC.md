# BiMail 产品定义书 v1.0

**Definition of Record｜概念、公理、规格与文案**

本文的写法服从产品自身的准则：不做装饰，每一个存在的条款都必须回答"它减少了什么摩擦"。凡不可验收的形容，一律翻译为可验收的量，或删除。修辞与规格在此分离——灵魂不靠形容词承载，而靠**可被违反、且可被检测的约束**承载。

**本次精确化包含三处实质修订（而非润色）：**

1. **"绝对无法窃取哪怕一个字节"** 是不可证明的过度承诺。已替换为明确的信任边界与威胁模型（§5.4），并禁用"绝对安全"表述。
2. **"没有发送按钮 + Ctrl/Cmd+Enter"** 在移动端不可实现。已精确化为**空态零控件**与**词形寄出**（§3.2）。
3. **"75% 的留白"** 是修辞而非规格。已替换为可测量的版心、间距与可见密度（§4.2）。

## 0. 定义与词汇

### 0.1 一句话定义（属加种差）

> **BiMail 是一个双人封闭、异步、只追加、无过程信号的纯文本留言板。**

形式化地：一个由**两个且仅两个**可写主体共同持有的、按**天**分组的**不可变文本序列**，以及承载它的**唯一界面**。

### 0.2 术语表（规范译名与禁用词）

| 规范术语 | 英文 | 精确定义 | 禁用替代词 |
|---|---|---|---|
| 墙 | Dyad | 唯一的会话实体，持有两个座位与一条留言序列 | 聊天、会话、房间、群 |
| 笔友 | Penpal | 占据一个座位的人类主体 | 好友、联系人、用户 |
| 座位 | Seat | 墙上的固定一侧（`a` / `b`），**留言的作者身份归属于座位，而非账号或设备** | 账号、成员 |
| 留言 | Entry | 一次已寄出的、不可变的纯文本，长度 1–8000 码点 | 消息、chat |
| 寄出 | Commit | 留言从本地草稿转为服务端不可变记录的唯一瞬间 | 发送成功 ✓✓ |
| 来访 | Visit | 一次打开页面的动作，同时是一次完整同步 | 上线、活跃 |
| 日 | Day | **写作者写下该留言时的本地日期**，非时间戳 | 几点几分、刚刚、5分钟前 |
| 派生语 | Derived line | 由状态计算出的一行居中说明（如座位建立日），不入库 | 系统通知 |
| 本地语 | Local line | 仅自己可见的一行状态说明（如"尚未寄出"），不上行 | 送达状态 |
| 恢复密钥 | Recovery key | 160 位熵、仅展示一次、服务端只存哈希的座位凭证 | 密码、验证码 |
| 过程信号 | Process signal | **被禁止的类**：在线、正在输入、已读、草稿、光标、停留时长 | — |

**语言即产品。** 上表右列的词汇不得出现在界面、文案、通知、文档与代码注释中。

## 1. 公理体系：灵魂的可判定形式

原稿把"没有已读""没有在线""没有正在输入"并列为若干克制之举。它们不是并列的品味选择，而是**同一条母公理的推论**。

### A1 二人封闭（Closure）
任一墙的可写主体数 ≤ 2；任一主体所属墙数 ≤ 1。
> 推论：不需要会话列表、不需要头像、不需要昵称。因为身份的信息量恰为 **1 bit**（我／非我），一个字重差异即已饱和承载。

### A2 不可撤销（Irrevocability）
留言一经寄出，任何主体（含作者、含运营方）不得修改或删除其内容，**唯一的例外是主体行使整体销毁权**（§5.6）。
> 言语是施为，不是草稿。此约束仅适用于**已寄出**；未寄出的文字仍完全属于作者（§3.6）。

### A3 过程不可观测（Process Opacity）——母公理
> **任何尚未成为"已寄出文字"的中间状态，都不得跨越座位边界。**

可观测的是**结果**，不可观测的是**过程**。以非干涉（noninterference）语言表述：

设 `Pub(σ) = (已寄出留言序列, 两个座位的建立日期)`，`Obs_b(σ)` 为座位 b 的全部可观测投影。

```
A3:  ∀σ, σ′.  Pub(σ) = Pub(σ′)  ⇒  Obs_b(σ) = Obs_b(σ′)
即   Obs_b 必须经由 Pub 因子分解：Obs_b = h ∘ Pub
```

**判定程序**：对任一客户端可见字段 `f`，若 `f` 的取值能在对方"未寄出任何新文字"时发生变化，则 `f` 违规。

由此**推导**（而非选择）出全部减法：

| 被删除之物 | 违规理由 |
|---|---|
| 已读回执 | 泄露阅读过程 |
| 在线状态 / 正在输入 | 泄露写作过程 |
| 精确到分秒的时间戳 | 可重建作息，等价于弱在线信号 |
| 云端草稿 / 多端草稿同步 | 泄露未寄出的文字 |
| 编辑历史 / 撤回痕迹 | 泄露犹豫过程 |
| 头像、昵称、个性签名 | 在 1 bit 身份之外附加表征 |

> **工程结论（重要）**：分秒时间戳不是"不好看"，而是**违规字段**。因此它在数据库层就不出库——客户端只能通过视图读到 `seq`（序号）与 `written_on`（日期），`created_at` 永不进入任何响应体（§5.2）。哲学不变量在此被编译为列级权限。

### A4 文字不灭（Durability）
留言一旦被确认寄出，在墙的存续期内对双方必然可读；未寄出的草稿不因刷新、断网、关闭而丢失。
> 推论：恢复密钥不是可选功能，而是 A4 的必要条件（§5.5）。

### A5 单一表面（One Surface）
产品只有**一个界面**、**一种内容物**（文本行）、**一种时间刻度**（天）。邀请、加入、离线、错误、超限、销毁、告别，全部表现为流中的一行文字，**不新增界面类型**（无弹窗、无 Toast、无红点、无独立通知中心）。

### A6 不主动触达（Non-interruption）
产品永不向墙外发出任何信号：无推送、无邮件、无短信、无角标。
> 产品不制造回访，只承接回访。"忘记"在此是特性，不是缺陷。

### A7 元素准入律（Admission）
一个元素被允许存在，当且仅当：

```
减少的摩擦 > 引入的摩擦  ∧  不新增对他者的义务  ∧  不新增表面  ∧  不违反 A1–A6
```

**派生准则**：不重复浏览器已提供的能力（查找、复制、缩放、翻译）。

## 2. 概念模型与状态机

### 2.1 实体

```
Dyad 1 ── 2 Seat 1 ── n Entry
Dyad 1 ── 1 Invite（单次、可过期）
```

### 2.2 墙的状态（三态，不可增）

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `nascent` | 仅座位 a 存在 | a 可写；邀请链接有效 |
| `open` | a、b 均在座 | 双方可写；邀请永久失效 |
| `closed` | 一方行使销毁权 | 只读自己的留言；不可写、不可邀、不可重开 |

**封缄的信**：`nascent` 期间 a 写下的留言，在 b 接受邀请后按其原始日期与顺序一次性呈现。等待的层积可见——此特性零新增机制。

### 2.3 座位的状态

`void → invited → seated → (lost → reseated) → closed`

`reseated` 仅更换座位所绑定的凭证，**不改变座位标识、不改变加入日期、不产生任何对方可见的痕迹**（否则违反 A3）。

### 2.4 留言的本地状态（三态）

`drafting → queued（离线）→ committed`

**不存在** `delivered` / `read` / `failed permanently`。寄出失败只回落到 `queued`，永不丢字。

## 3. 交互规格（逐事件）

### 3.1 首次抵达

1. 邀请链接形如 `https://<域>/#i=<32字符token>`。**token 置于 fragment**：不进入服务器日志、不进入 `Referer`、不进入 CDN 缓存键。
2. 页面读取 fragment 后立即 `history.replaceState` 清除，防止历史记录与截图泄露。
3. 匿名身份建立（Supabase anonymous sign-in），无任何注册表单。
4. 调用 `accept_invite(token)`：单事务、行锁、原子占座。
5. 成功后展示**恢复密钥一屏**：等宽字体、可复制、可下载为 `.txt`，一行说明——"我们不留副本。丢了它，就丢了这堵墙。"必须显式点击"我已保管"方可进入。
6. 进入墙。若 a 已写信，视图定位到第一封信的日期组首；若墙为空，显示空墙文案。
7. 桌面端自动聚焦输入框；移动端**不**自动聚焦（避免键盘遮挡半屏）。
8. 首次进入时，输入框上方出现一行淡字，永久保留至第一次成功寄出："`Enter` 换行，`⌘/Ctrl + Enter` 寄出。"

**失败分支**（均以流中一行文字表达，无弹窗）：
- token 已消费 / 已过期 / 座位已满 → "这堵墙已有两位笔友。"（不透露是谁、何时）
- 调用者已属他墙 → "你已经有一堵墙了。"（不提供切换入口，A1）

### 3.2 写信（输入框逐条规格）

| 项 | 规格 |
|---|---|
| 形态 | 常驻底部的 `textarea`，无边框、无背景、无焦点光环 |
| 空态 | **零控件**：无寄出词、无快捷键提示、无字数计 |
| 非空态 | 右下角出现两个同字号淡字元素：`寄出`（词，非按钮外观）与 `⌘⏎` / `Ctrl ⏎` |
| `Enter` | 换行 |
| `Ctrl/Cmd + Enter` | 寄出 |
| **IME 守卫** | `keydown` 中若 `event.isComposing \|\| event.keyCode === 229` 则**不寄出**。中文/日文候选词确认的回车绝不触发寄出（P0） |
| 重复触发 | 同一 `client_uuid` 幂等；连按只产生一条 |
| 空白 | `trim` 后为空则静默忽略，无提示 |
| 归一化 | 连续 ≥3 换行折叠为 2；制表符转 2 空格；剔除零宽字符（U+200B–200D、U+FEFF） |
| 粘贴 | 强制 `text/plain`，剥离一切富文本 |
| 渲染 | `textContent`，不解析 Markdown、不生成 `<a>`、不做链接预览（XSS 天然免疫） |
| 上限 | 8000 码点。超限时保留可容纳部分，下方一行淡字："已超出 N 字，未纳入。" |
| 自增高 | 最小 1 行（48px），最大 40vh，超出内滚 |
| 草稿 | 本地保存，节流 300ms，**永不上传**（A3 的实现，而非仅为体验） |
| 移动端 | 依据 `visualViewport` 吸底，尊重 `env(safe-area-inset-bottom)` |

> **"没有发送按钮"的精确形式**：不是没有寄出控件，而是**空输入时不存在任何控件**，且寄出控件是一个与正文同字号、无边界、无背景、无彩色的**词**。它不与文字争夺注意力，但它在触屏上必须存在。

### 3.3 寄出的原子序列

1. 生成 `client_uuid`（v4）与 `written_on`（客户端本地日期）。
2. 乐观追加至流末尾（120ms 淡入），输入框清空，草稿清除。
3. `POST /rpc/post_entry`。
4. 成功：以返回的 `seq` / `id` 校正本地记录，滚动至底部（160ms）。
5. 失败：该条回落为 `queued`，其下出现一行**本地语**"尚未寄出，联网后自动寄出。"——仅自己可见。
6. 全程无"发送成功"提示。**出现在墙上，就是成功。**

### 3.4 来访与同步

- **触发**：挂载时；`visibilitychange → visible` 且距上次同步 >30s；下拉手势（阈值 64px）；寄出成功后。
- **不做**：轮询、长连接、Realtime、Service Worker 推送。
- **分页**：首屏最近 120 条；向上加载 120 条；不显示总条数（计数是装饰）。DOM 上限 ≈240 条，故无需虚拟列表。
- **定位**：本地记录 `last_seen_seq`（**仅 localStorage，绝不上行**）。打开时若存在新留言，视图停在你上次离开之处，**不加任何"新"标记**——位置本身即唯一提示。
- **自愈**：无连接即无断线。每次来访都是一次完整同步。

### 3.5 日分组算法

- 排序键：服务端 `seq`（严格单调）。
- 分组键：`written_on`（写作者本地日期）。
- 算法：**游程分组**（run-length）——相邻且日期相同者归为一组，日期变化即插入新标签。
- **不做时区换算、不显示时区名、不显示"今天/昨天"**（相对时间暗示"现在"，重新引入时钟感）。
- 格式：同年 `11月8日`；跨年 `2026年11月8日`。
- **已知取舍**：跨时区或跨日界写作时，日期标签可能非单调重复。规格立场：**宁可重复，不可撒谎，绝不重排。** 每条留言头上的日期，永远是写下它的那个人的那一天。

### 3.6 未寄出文字的撤回

`queued` 状态的留言，其"尚未寄出"字样可点击，展开一行确认："撤回这段未寄出的文字。"

> A2 的精确边界：不可撤销约束的是**已发生的施为**。未寄出的文字尚不构成言语，仍完全属于作者。

### 3.7 唯一的设置面

入口为流底部一行淡字"设置"（非齿轮图标）。内容为纯文本一页，共四行：

1. 查看恢复密钥（需二次确认，展示后不再自动隐藏）
2. 导出全部文字（`.txt`）
3. 让其他设备离开（注销除本次以外的全部会话）
4. 离开并销毁我的文字（不可逆）

无版本号徽章、无主题开关、无字体选择、无统计面板。

## 4. 视觉与排版规格（可验收）

### 4.1 色彩令牌（全站色相数 = 1）

| 令牌 | 亮色 | 对比度 | 暗色 |
|---|---|---|---|
| 纸 | `#F5F3EF` | — | `#171614` |
| 我 | `#1A1917` / 字重 500 | ≈15.9:1 | `#E8E4DC` / 500 |
| 笔友 | `#2E2C28` / 字重 400 | ≈12.6:1 | `#C9C4BA` / 400 |
| 淡语（日期、派生语、本地语） | `#6E6A61` | ≈4.9:1 | `#9A958B` |

**验收**：正文对比度 ≥12:1，淡语 ≥4.5:1；全站无任何强调色、无饱和度 >6% 的色值。暗色跟随 `prefers-color-scheme`，**不提供开关**（零新增元素）。

### 4.2 "留白"的可测定义（替代"75%"）

- 版心 `max-width: 600px`（中文约 35 字/行），行高 1.75，正文 17px。
- 单条留言块宽 ≤ 版心 86%；`margin-left:auto`（我）/ `margin-right:auto`（笔友）。
- **块内文字一律左对齐**。"居右"指**文本块整体靠右**，不是文字右对齐——后者使长段落左缘锯齿化，摩擦剧增。
- 桌面 ≥1280px 时两侧留白 ≥53%；移动端左右边距 20px（诚实：移动端不存在 75% 留白）。
- 相邻留言间距 24px；日期组上间距 40px、下间距 16px。
- 屏内同时可见留言数中位数 ≤4。

### 4.3 身份编码（1 bit 的三重冗余）

水平位置 + 字重 + 墨色，任一通道单独失效（窄屏、暗色、色觉差异）仍可辨识。屏幕阅读器通道：每条前置视觉隐藏前缀"你："/"笔友："。

### 4.4 字体与动效

- 单一系统字族：`-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`；等宽仅用于恢复密钥。**零 Web Font。**
- 字号三种：17 / 13 / 13。字重两种：400 / 500。
- 全站唯一动效：新留言 120ms 淡入（无位移）+ 寄出后 160ms 滚动。`prefers-reduced-motion` 时全部为 0。
- **焦点可见性的准入辩论**：原稿"无焦点光环"与无障碍冲突。裁定——鼠标聚焦无光环；键盘导航（`:focus-visible`）必须有 1px 中性描边。**不可见的焦点是摩擦，不是极简。**

## 5. 数据与安全的精确边界

### 5.1 技术选型与其代价

Vue 3 + Vite + TypeScript，静态托管于 GitHub Pages + 独立域；Supabase Auth（匿名）+ Postgres + RLS；**不启用 Realtime / Storage / Edge Functions**。不引入 `supabase-js`，手写约 150 行 Auth + PostgREST 客户端；不引入路由库（单界面 + 单设置面）。

**预算（验收项）**：首屏 JS ≤55KB gzip，CSS ≤6KB，首屏请求 ≤4，零图片、零 Web Font、零第三方脚本；4G 中低端机 LCP ≤1.0s，INP ≤100ms。

### 5.2 模式（关键约束已内联注释）

```sql
revoke all on all tables in schema public from anon, authenticated;

create table dyad (
  id uuid primary key default gen_random_uuid(),
  state text not null default 'nascent'
        check (state in ('nascent','open','closed')),
  created_at timestamptz not null default now()
);

create table seat (
  dyad_id uuid not null references dyad(id) on delete cascade,
  slot char(1) not null check (slot in ('a','b')),
  -- on delete restrict：运维清理匿名用户时被外键挡住 → A4 的数据库级保护
  user_id uuid not null unique references auth.users(id) on delete restrict,
  recovery_hash bytea not null,
  joined_on date not null default (now() at time zone 'utc')::date,
  primary key (dyad_id, slot),
  unique (user_id)          -- 「无会话列表」= 一条 UNIQUE 约束（A1）
);

create table entry (
  id uuid primary key default gen_random_uuid(),
  dyad_id uuid not null references dyad(id) on delete cascade,
  slot char(1) not null,
  seq bigint generated always as identity,
  body text not null check (char_length(body) between 1 and 8000),
  written_on date not null,
  client_uuid uuid not null,
  created_at timestamptz not null default now(),  -- 仅排序与审计，永不出库
  unique (dyad_id, client_uuid),                  -- 幂等寄出
  foreign key (dyad_id, slot) references seat(dyad_id, slot)
);
create index on entry (dyad_id, seq);

-- 唯一读通道：分秒不出库（A3 的列级实现）
create view v_entry with (security_invoker = true) as
  select id, seq, slot, body, written_on from entry;

create view v_seat with (security_invoker = true) as
  select slot, joined_on from seat;   -- 天粒度、一次性、双方共知
```

`created_at` 与 `client_uuid` 不在任何视图中；`authenticated` 对基表无 `select` 权限。**A3 由此从一条哲学主张变成一个字段断言。**

### 5.3 RLS 与只追加

```sql
create function my_dyad() returns uuid
language sql stable security definer as
$$ select dyad_id from seat where user_id = auth.uid() $$;

alter table entry enable row level security;
create policy read_own on entry for select
  using (dyad_id = my_dyad());
-- 无 insert / update / delete 策略，且相应权限已 revoke
-- 一切写入经由 security definer RPC：post_entry / accept_invite /
--   rebind_seat / close_and_erase / revoke_other_sessions
```

`post_entry` 校验：调用者在座、墙为 `nascent|open`、`written_on` 落在服务端日期 ±2 日内（否则取服务端日期）、长度合规、`client_uuid` 幂等。

### 5.4 不变量 → 机制 → 验收

| 不变量 | 一阶表述 | 实现机制 |
|---|---|---|
| I1 | `∀d: \|seats(d)\| ≤ 2` | `slot ∈ {a,b}` + 主键 + 占座 RPC 行锁 |
| I2 | 客户端不可执行 `UPDATE/DELETE` on entry | 权限撤销 + 无策略 + 仅 RPC 写入 |
| I3 | `Obs_b = h ∘ Pub` | 视图字段集 + 无 Realtime + 草稿本地化 |
| I4 | 已寄出者恒可读 | `on delete restrict` + 恢复密钥 + 幂等队列 |
| I5 | `∀u: \|dyads(u)\| ≤ 1` | `seat.user_id UNIQUE` |

### 5.5 威胁模型（含"我们不承诺什么"）

| 攻击面 | 结论 | 缓解 / 残余风险 |
|---|---|---|
| 非成员持会话 ID 直接查询 | **拒绝，返回零行** | RLS + `my_dyad()`；渗透用例 T1 |
| **未消费**的邀请链接被第三方获得 | **可冒充占座** | 192 位熵、7 天时效、单次消费、fragment 不入日志、占座后永久失效；**残余风险明示** |
| 已消费链接泄露 | 无能力 | token 即时作废 |
| 一方浏览器存储被他人取得 | 可读写该座位 | "让其他设备离开"（注销其他会话）；但无法清除该设备本地草稿，明示 |
| 平台方 / 数据库运营方 | **可读明文** | **BiMail 不提供端到端加密**（见 §6） |
| 供应链（托管方、npm） | 可注入脚本 | 严格 CSP、锁文件、直接依赖 ≤10、零第三方脚本；静态托管方仍属信任根 |
| 内容层 XSS | 免疫 | `textContent` + CSP |
| 时序侧信道（由序号差分推断作息） | **不可重建** | 分秒不出库，仅日期可见 |

**文案禁令**：不得使用"绝对安全""无法窃取任何一个字节""军事级加密"。允许表述：**"传输加密、静态加密、行级隔离；密钥在你手里，明文在库里。"**

### 5.6 恢复密钥（A4 的必要条件）

- 客户端生成 160 位熵，Base32 呈现为 32 字符；服务端仅存 SHA-256。
- 展示一次，可复制、可下载 `.txt`；服务端无副本、无邮箱、无手机号。
- `rebind_seat(key)`：校验哈希、墙未关闭、调用者无座 → 事务内更换 `seat.user_id`，旧凭证永久失效；**座位标识与加入日期不变，对方无感**。
- 节流：每调用者每小时 5 次。
- **诚实告知**：丢失密钥且丢失设备 ⇒ 座位不可恢复。这不是可以靠"客服"绕过的设计——没有客服，就没有第三个人能读你们的墙。

### 5.7 销毁与数据权利

- 单方"离开并销毁"：硬删除自己全部留言 → 墙置 `closed` → 对方仍可读自己的留言，墙不可再写、不可再邀、不可重开。
- **不释放座位**（释放即引入第三人，违反 A1）。
- 对方留言的处置权属于对方。
- 导出格式（纯文本，可携带）：

```
BiMail · 导出于 2026年11月12日
—— 11月8日
你：……
我：……
```
文件名 `bimail-2026-11-12.txt`。以导出替代应用内搜索（A7 派生准则：不重复浏览器能力）。

## 6. 非目标清单（逐条拒绝理由）

| 不做 | 拒绝依据 |
|---|---|
| 实时通道、推送、邮件、角标 | A6 |
| 已读、在线、正在输入、云端草稿 | A3 |
| 编辑、撤回已寄出、编辑历史 | A2 |
| 群、多会话、会话切换 | A1 + `UNIQUE` 约束 |
| 头像、昵称、签名、账号体系 | A1 推论（身份仅需 1 bit） |
| 图片、语音、表情包、富文本、Markdown | 文字是唯一主角 |
| 可点击链接、链接预览 | 外部抓取即泄露；视觉噪音 |
| 应用内搜索、主题、字体设置、统计面板 | A7 |
| **AI 代写、润色、摘要、自动回复** | **"二人"指两个人类主体。一旦允许机器代笔，收信人无法确知他在与谁通信——A1 的语义即被摧毁。BiMail 中机器的参与度为零。** |
| **端到端加密** | 密钥管理必然新增表面与不可恢复风险，与 A5/A7 冲突。**明确不承诺，并在文案中禁止暗示。** |

## 8. 度量与反度量

- **北极星**：每周**双向回合数**（留言序列中座位交替次数 ÷ 2）。它度量对话，不度量停留。
- 辅助：首封信长度中位数；往返间隔（天）中位数；7 日内自然回访率。
- **反指标（明确不优化、不上看板）**：会话内停留时长、日消息量、打开次数、通知点击率（不存在）。
- 埋点：服务端按**天**聚合的计数，不含正文、不含 IP、不含精确时刻、不含阅读位置；部署级总开关可完全关闭。

## 9. 验收清单（Definition of Done）

**功能与输入**
1. 中文/日文 IME 候选确认回车不寄出（P0）
2. 连按 `⌘/Ctrl+Enter` 只产生一条
3. 空白输入静默忽略
4. 粘贴富文本被剥离为纯文本
5. 8000 字边界与超限提示正确
6. 刷新、关闭、断网 30 分钟后草稿仍在
7. 离线排队 5 条，恢复后按序寄出且无重复
8. 未寄出者可撤回；已寄出者无任何撤回入口

**同步与渲染**
9. 无 Realtime 连接、无轮询（网络面板断言）
10. 定位到上次离开处，且无任何"新"标记
11. 1000 条历史下分页与滚动流畅，DOM ≤240 条
12. 跨时区日期游程分组不重排、不撒谎
13. 暗色、`prefers-reduced-motion`、键盘可达、`:focus-visible` 全部通过
14. 对比度与色相数断言通过

**安全（渗透用例）**
15. T1：第三 uid 直接查询 `entry` / `v_entry` 返回零行
16. T2：`v_entry` / `v_seat` 字段集不含 `created_at`、`client_uuid`、任何阅读或在线字段
17. T3：`has_table_privilege('authenticated','entry','UPDATE/DELETE')` 为假
18. T4：邀请二次消费失败；占座后 token 永久失效
19. T5：清缓存后用恢复密钥换回座位成功，旧 uid 读取零行
20. T6：`seat.user_id UNIQUE` 阻止跨墙占座
21. T7：删除匿名用户的运维操作被外键阻止（A4）
22. T8：CSP 生效，无内联脚本、无第三方请求

**性能**
23. 首屏 JS ≤55KB gzip、请求 ≤4、零 Web Font
24. 4G 中低端机 LCP ≤1.0s，INP ≤100ms

# BiMail：一堵只有两个人的墙

即时通讯把人与人的距离压缩到了秒级，也把"随时在线"变成了一种义务。"正在输入"催促你，已读回执审判你，群聊列表切割你。

BiMail 只做一件事：**让两个人交换文字，而不必交换自己的状态。**

它是一堵墙，只有两个座位。没有头像，没有昵称——因为只有一个人可能是"对方"，身份不需要被表征，只需要被区分：你的话靠右、稍深；他/她的话靠左、稍轻。没有分秒，只有日期。"哪天写的"比"几点几分"更像一封信。

写下，`⌘/Ctrl + Enter`，离开。下次再来读。

我们删掉的，都是**过程**：在线、正在输入、已读、草稿、犹豫。它们不属于对方。留在墙上的只有**结果**——你真正写下的那些字。写下即不可撤回，因为言语是承诺，不是草稿。

这里没有图片、表情包，也没有替 you 写字的 AI。文字的重量，来自它是人所写。

我们不承诺端到端加密，也不索要你的邮箱与手机号。只有一把钥匙，展示一次，由你自己保管——我们不留副本。丢了它，就丢了这堵墙。这不是缺陷：没有第三个人能替你们开门。

BiMail 不推送、不提醒、不制造回访。它只承接你想起来的那一刻。

**它不想成为下一个微信。它只想做你口袋里的那张信纸。**

如果你也有这样一位笔友——不常联系，但每一次交谈都足够真诚——把链接交给他/她。

在这个喧嚣的数字世界里，为你们保留一堵安静的墙。
